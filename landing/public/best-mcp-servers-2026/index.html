TRUST CHECK

Vendor server or lookalike? Read the registry name

Popular names get reused. In the same 23 October 2026 snapshot, besides the vendor's own entry, the Official MCP Registry held 27 other servers with "figma" in the server name, 16 with "stripe", 12 with "notion" and 12 with "sentry". Some are unrelated names that merely contain the word, some are useful community tools built on the vendor's API. The display name tells you nothing about who published a server; the registry namespace does.

  • Reverse-DNS names such as com.notion/mcp or com.stripe/mcp can only be published after proving control of that domain (DNS or HTTP check), per the registry's authentication docs.
  • GitHub names such as io.github.getsentry/… require GitHub login, and an organization namespace requires being an owner of that organization.
  • Anything else (a gateway, a fork, a personal namespace) is a different publisher. Read its repository and required secrets before you hand it an API key.

MCPfinder shows the registry name, source and warnings for every result, so your agent can apply this check before generating an install config.

There is no fixed top-10, but a safe starting point is the server the vendor publishes itself. Is MCPfinder a directory website only?
No. It is primarily an MCP server your AI client calls. The mcpfinder.dev site explains install and discovery; the product experience is agent-native search.
How do I browse categories?
Use the browse_categories tool to list categories with counts or top servers in areas like database, filesystem, communication, or security.
How do I tell a vendor's own MCP server from a lookalike?
Check the server name in the Official MCP Registry. A reverse-DNS name such as com.notion/mcp can only be published by someone who proved control of that domain, and io.github.getsentry/… requires being an owner of that GitHub organization. A similar name under a different namespace is not proof that the vendor published it; check the namespace and the linked repository.
Do Smithery-hosted MCP URLs still work?
Smithery announced that server URLs on run.tools and server.smithery.ai, its API, CLI and SDKs would stop working on 31 October 2026. Switch to the vendor's own MCP URL; see the MCPfinder Smithery alternative guide. MCPfinder does not use Smithery as a source.
